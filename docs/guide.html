۰پیش‌نیازها

  • .NET 10 SDK — نسخه در global.json قفل است.
  • ابزار EF (فقط برای ساخت مایگریشن): dotnet tool install --global dotnet-ef
  • SQL Server — یا همان داکر مرحله ۲ (نصب جدا لازم نیست).

۱ساخت پروژه از قالب

git clone https://github.com/satarniakan/EmptyFrawework.git
cd EmptyFrawework
dotnet new install .
mkdir MyProject
cd MyProject
dotnet new empty-platform -n MyProject
cd MyProject   # خروجی داخل پوشهٔ هم‌نام می‌نشیند
نام‌ها خودکار جایگزین می‌شوند: Platform.X می‌شود MyProject.X. ساختار تخت است؛ تنها پروژهٔ اجرایی MyProject.App است — همان را اجرا کنید.

۲دیتابیس (یکی از سه راه)

راهدستورکی؟
الف) داکر (پیشنهاد)docker compose up --build سپس مرورگر روی http://localhost:8080سریع‌ترین؛ SQL Server جدا نمی‌خواهد

ج) خودکارهیچ‌کار — اپ با MigrateAsync هنگام استارتاپ جدول‌ها را می‌سازدتوسعه روزمره

بعد فایل Platform.App/appsettings.json.example را به appsettings.json (کنار خودش) کپی کنید و رشته اتصال + Identity:FirstAdminPhoneNumber (شماره خودتان) را بگذارید. این فایل در گیت نمی‌رود.

۳بیلد و تست

dotnet build MyProject.slnx
dotnet test MyProject.Tests/MyProject.Tests.csproj

هر دو باید سبز شوند (≈۱۳۰ تست). اگر قرمز شد همان خطا را بخوانید — معمولاً رشته اتصال است.

۴اولین اجرا و ادمین‌شدن

dotnet run --project MyProject.App
  1. با شماره‌ای که در FirstAdminPhoneNumber گذاشتید وارد شوید (کد پیامکی؛ در حالت توسعه با Dev:AutoLoginPhone و مسیر /dev-login بدون پیامک).
  2. اولین ورودِ آن شماره، نقش ادمین می‌گیرد؛ بقیه «کاربر» می‌شوند.
  3. منو را ببینید: مدیریت کاربران، تنظیمات، گزارش رویدادها.

۵نقشه پروژه‌ها و قانون طلایی

پروژهنقشدست می‌زنید؟
MyProject.Appتنها پروژه اجرایی — مایگریشن‌ها و سه نقطه اتصال دامنه اینجاستبله (فقط همین)

۶افزودن ماژول دامنه قدم‌به‌قدم (مثال: سفارش‌ها)

  1. انتیتی: کلاس در پروژه جدا (مثلاً Orders/Order.cs، ارث از AuditableEntity برای حذف نرم و رد پیگیری خودکار).
  2. مدل EF: کلاس IPlatformModule با ConfigureModel و ثبت با services.AddSingleton<IPlatformModule, OrdersModule>().
  3. ریپازیتوری + سرویس: اینترفیس و پیاده‌سازی؛ چندنوشته‌ها را در ExecuteInTransactionAsync بگذارید. واحد کار اختصاصی: اینترفیس از IPlatformUnitOfWork + کلاس مشتق از PlatformUnitOfWork.
  4. مجوز: کلید (مثلاً orders.manage) را به IPermissionCatalog اضافه کنید — policy و آیتم نقش‌ها خودکار می‌آیند؛ صفحه با [Authorize(Policy = "orders.manage")] بسته می‌شود.
  5. منو: یک NavItem.Link با همان کلید مجوز به INavProvider اضافه کنید.
  6. مایگریشن: dotnet ef migrations add AddOrders --project MyProject.App --startup-project MyProject.App
  7. صفحه: Razor در میزبان + ثبت در منو. برای آپلود فایل از IFileStorage، برای شماره سند از INumberSeries، برای ایمپورت اکسل از ExcelImporter استفاده کنید.
اعلان/پیامک/ایمیل/پوش لازم داشتید؟ فقط INotificationService و IOutboxService را صدا بزنید — ارسال و retry با پردازنده صف است.

۷اتصال موبایل و API

  • ورود: POST /api/v1/auth/otp/verify (پیامک) یا POST /api/v1/auth/login (رمز — وقتی پیامک قطع است) → توکن pat_…
  • استفاده: هدر Authorization: Bearer pat_… — مستندات کامل در Development: /openapi/v1.json
  • مدیریت نشست: GET/DELETE /api/v1/auth/tokens (لیست و لغو، از جمله «خروج از همه دستگاه‌ها»)

۸چک‌لیست رفتن به Production

  • Sms:Provider=Kavenegar + کلید واقعی؛ قالب‌ها در صفحه تنظیمات بازبینی شوند.
  • Captcha:Provider=Turnstile + SiteKey/SecretKey.
  • Payment:Provider=ZarinPal + MerchantId (مبالغ به تومان).
  • Push:Vapid با npx web-push generate-vapid-keys.
  • Support:ImpersonationEnabled خاموش بماند مگر برای پشتیبانی.
  • HTTPS + بکاپ دوره‌ای دیتابیس + نگهداری لاگ Serilog.

۹عیب‌یابی

علامتعلت و راه‌حل
خطای اتصال SQL هنگام runرشته اتصال appsettings.json و بالابودن SQL Server (یا docker compose up sqlserver)
منوی ادمین دیده نمی‌شودبا شماره ادمین اول وارد نشده‌اید؛ نقش را در /admin/users چک کنید
policy ناشناخته در صفحه جدیدکلید مجوز در IPermissionCatalog نیست یا املایش با Policy فرق دارد
مایگریشن جدول ماژول را نساختماژول در DI ثبت نشده (AddSingleton<IPlatformModule,…>) یا پروژه اشتباه به dotnet ef داده‌اید
کد OTP نمی‌رسدSms:Provider روی Fake است (لاگ را ببینید) یا سقف ۳ کد در ۱۵ دقیقه خورده‌اید
